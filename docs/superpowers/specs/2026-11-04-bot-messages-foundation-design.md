# 指令与消息改版一：消息模板、提醒和指令可见性

日期：2026-11-04
上级计划：指令与消息改版分三个子项目，本文是第一个。

| 子项目 | 内容 |
| --- | --- |
| 一（本文） | 共用消息模板、全局 @ 限制、管理指令默认隐藏、报错文案、`/status` 和 `/help` |
| 二 | 指令输入：参数中文名和说明、用自动补全代替手填 ID、时长改选项、数字范围、分页 |
| 三 | 消息和交互：纯文字回复改成卡片、确认按钮、更多交互面板 |

## 1. 目标

用户希望参考 MEE6、Dyno、Carl-bot 等机器人和 Discord 官方指南，改进指令的操作和机器人发出的消息。这一版先打底：消息只用一套模板和五种颜色，机器人不会误发全服提醒，普通成员看不到用不了的指令，出错时说清楚出了什么事、怎么办。

成功标准：
- 全部测试通过，部署脚本打印 DEPLOY OK。
- 用户在开发服务器里检查过：普通成员账号的 / 列表里没有管理指令和开发指令；`/status`、`/help`、`/giveaway start`、一条管理日志、两三种报错的颜色、标题和文案符合本文。我不能登录 Discord，这一步由用户做。

## 2. 现在的问题（2026-11-04 读代码统计）

1. **颜色太杂。** 机器人和网页发出的 embed 用了 26 种颜色：13 个 `discord.Color` 预设（含 `/status`、`/avatar` 用的随机色）和 13 个十六进制值。同一类消息颜色也不统一，比如成功提示有 `green()`、`0x57F287`、`0x5A9E6F` 三种绿。
2. **标题。** 几乎每个标题前都有 emoji，有的叠两个（"⏳🔨 你已被临时封禁于…"）。管理日志标题是英文大写："WARN | 案件 #3"。
3. **同一条消息写了两份。** 抽奖消息机器人（`giveaway.py`）和网页（`routes.py`）各拼一遍；系统日志的级别颜色在 `botlog.py` 和 `routes.py` 各存一份；身份组面板由网页发出时标题原样显示，机器人重建面板时会在前面加 🏷。
4. **没有 @ 限制。** `main.py` 没有设 `allowed_mentions`。纯文字回复会把管理员或成员写的文字原样发出，例如 `/kick` 回复里的原因、开奖通知里的奖品名。机器人有「提及 @everyone」权限时，这些文字里的 @everyone、@here 和身份组提及会真的提醒。
5. **管理指令所有人可见。** 56 处 `commands.has_permissions` 只在执行时检查，没有一处设 Discord 默认权限。普通成员在 / 列表里能看到 41 条管理指令（含 `/giveaway` 组），点了才被拒。
6. **开发和主人指令全局注册。** hot_update、load、unload、extensions、sync、setstatus、resetstatus、setbio 这 8 条出现在每个服务器的 / 列表里。`/help` 和控制台的指令列表（来自 `health.json`）也会列出 setstatus、resetstatus、setbio。
7. **报错说不清。** 机器人缺权限时显示英文权限名（"我缺少所需权限：kick_members"）；成员没权限时只说"你没有权限使用这个指令"，不说缺哪个；参数错时只说"参数有误，请检查后重试"；未知错误是"😵 出了点问题"。
8. **`/status` 公开主机信息。** 任何人都能看到服务器主机的 CPU、内存、磁盘占用和操作系统版本；颜色随机；页脚写"请求者: xxx"。
9. **`/help` 公开发送。** 菜单发在频道里，谁都能点下拉框，改掉别人正在看的页面；列表不按权限过滤。

## 3. 范围

**要改：**
- 机器人里所有 embed（`rinbot/cogs/` 下除 `netease.py` 外的全部模块）。
- 网页发到 Discord 的 5 种 embed：系统日志、系统日志测试消息、审计日志测试消息、身份组面板、抽奖消息（`website/routes.py`）。
- 控制台里身份组面板预览的颜色和默认标题（`website/static/js/message-preview.js`、`console.css` 的 `.preview-embed--roles`）。
- 报错处理（`cogs/errors.py`）、全局拦截（`cogs/globalsettings.py`、`cogs/_botlog_helper.py` 的 `check_component`）、开发模块自己的报错（`cogs/dev.py`）。
- 所有带权限检查的指令、8 条开发和主人指令、`/sync`、`/hot_update` 的同步逻辑。
- `/status`、`/help`、`health.py` 导出的指令列表。

**保持不变：**
- 纯文字回复（一百多处 `ctx.send("✅ …")` 之类）和指令里自己发的校验报错（比如"❌ 无效的时间格式"、层级检查）：留给子项目三。
- 指令名、参数名、参数类型、指令说明文字（含 `[管理]`、`[Dev]` 前缀）：留给子项目二。
- 欢迎卡片图片、等级卡片图片、网易云模块（`netease.py` 不进仓库）。
- 机器人启动时不自动同步指令（现状如此，见第 10 节）。
- 已经发在频道里的旧消息：只有机器人之后编辑它们时才会换成新样子（开奖、重建身份组面板）。

## 4. 消息模板

### 4.1 五种消息

| 种类 | 颜色 | 用在 |
| --- | --- | --- |
| 信息 `info` | 小凛粉 `#EB8BAC` | 查询结果、列表、面板、正在播放、欢迎、身份组面板、进行中的抽奖、公告 |
| 成功 `success` | 完成绿 `#3BA55D` | 操作完成、设置已保存、已加入队列、开奖有人中奖、测试消息 |
| 注意 `warning` | 注意黄 `#F0B232` | 冷却中、维护中、指令已停用、只完成了一部分 |
| 失败 `error` | 失败红 `#ED4245` | 报错、被拦下 |
| 日志 `log` | 日志灰 `#80848E` | 日志里的一般事件、道别、无人参加的抽奖 |

小凛粉和控制台 Discord 预览条的颜色（`console.css` 的 `.preview-embed`）是同一个值。

**日志按事件分色**，管理日志、审计日志、自动审核记录都用这张表：

| 事件 | 颜色 |
| --- | --- |
| 新增、恢复：成员加入、解除封禁、解除禁言、超时已解除、频道或身份组已创建 | 完成绿 |
| 修改、警告、限制：消息被编辑、昵称或身份组变更、频道或身份组已修改、服务器设置已更新、警告、禁言、超时禁言、自动审核处理 | 注意黄 |
| 删除、处罚：消息被删除、批量删除、清理消息、踢出、封禁、临时封禁、频道或身份组已删除 | 失败红 |
| 其他：成员离开、语音进出和切换、表情更新、清除警告 | 日志灰 |

系统日志按级别分色：错误→失败红，警告→注意黄，配置变更→完成绿，信息→日志灰。

### 4.2 写法

- **标题** 一句话说结果或内容，不加 emoji，不用英文大写。例："案件 #12：警告"、"消息被删除"、"小凛的运行状态"、"你已被踢出 {服务器名}"。
- **正文** 写一两句。需要并列的信息放字段，不在正文里拼"**奖品:** …"这种标签行。
- **字段名** 用短词：成员、管理员、原因、时长、频道、奖品。不加 emoji。数字和时长不再包代码格式。
- **字段排列** 短内容（成员、管理员、时长）并排，长内容（原因、消息内容）独占一行。
- **页脚** 只放和这条消息有关的编号或提示（"抽奖 #3"、"菜单 2 分钟后失效"），不写"请求者"、不写品牌口号。
- **时间戳** 只加在日志类消息上，Discord 会按看的人自己的时区显示。
- **作者行** 只在两个地方用：系统日志的"系统日志 · 级别"，和正在播放卡片的状态行。
- **语气** 功能消息简短直白。只有 `/help` 首页、欢迎消息、升级提示保留小凛的颜文字。
- **下拉选项**（`/help` 的模块菜单）可以保留 emoji 图标，它们是菜单图标，不是标题。

### 4.3 长度上限

模板按 Discord 的上限截断，超出部分用"…"结尾：标题 256 字，正文 4096 字，字段名 256 字，字段值 1024 字，页脚 2048 字，作者行 256 字，字段最多 25 个。全部文字加起来超过 6000 字时，再截正文。值为空的字段直接跳过。

### 4.4 代码结构

- **`rinbot/rincore/embeds.py`**（新，不依赖 discord.py，机器人和网页都能用）：
  - 五种颜色常量和 `COLORS` 表。
  - `build(kind, title=None, description=None, fields=(), footer=None, author=None, timestamp=None, ...) -> dict`：按第 4.2、4.3 节的规则生成 Discord embed 的 JSON，`kind` 不是五种之一时报错。
  - `event_kind(event) -> kind`：第 4.1 节日志分色表。
  - `giveaway(...) -> dict`：抽奖消息，机器人和网页共用（第 5.3 节）。
  - `LOG_LEVELS`：系统日志级别的颜色和中文名，`botlog.py` 和 `routes.py` 都从这里读。
- **`rinbot/cogs/_messages.py`**（新，机器人专用，沿用 `_botlog_helper.py` 的放法）：
  - `embed(kind, title=None, description=None, **kw) -> discord.Embed`：把 `build()` 的结果转成 `discord.Embed`，调用方之后仍可设缩略图、大图。
  - `send(target, embed, *, private=False, view=None)`：`target` 是指令上下文或交互。`private=True` 时斜杠指令和交互用私密回复；`r!` 前缀指令没法私密，15 秒后自动删除。
- 各模块不再自己写颜色值。网页的 `routes.py` 也改用 `rincore.embeds`。

### 5.3 抽奖消息

`rincore.embeds.giveaway()` 生成三种状态，机器人 `/giveaway start`、网页创建、机器人开奖都调用它：

- **进行中**（信息）：标题"抽奖：{奖品}"；字段"中奖人数 {n} 人"、"结束时间 {相对时间}（{具体时间}）"、"发起人 {@发起人}"（网页创建时没有发起人就不显示）、"参加条件 需要 {@身份组}"（有限制时）；页脚"点下方按钮参加"。
- **已开奖**（成功）：标题"抽奖结束：{奖品}"；字段"中奖者 {@…}"；页脚"抽奖 #{id}"。
- **无人参加**（日志）：标题"抽奖结束：{奖品}"；正文"没有符合条件的参加者。"；页脚"抽奖 #{id}"。

发出进行中的消息时还没有抽奖编号（机器人和网页都是先发消息、再写库），所以编号只在开奖后出现。

## 6. 全局 @ 限制

`main.py` 的 `HybridBot` 设 `allowed_mentions=AllowedMentions(everyone=False, roles=False, users=True, replied_user=False)`。discord.py 会把它当作所有消息、交互回复和后续消息的默认值。

- 不管文字从哪来，@everyone、@here 和身份组提及都只显示文字、不提醒。
- 照常提醒具体的人：开奖通知里的中奖者和发起人、升级提示、自动审核点名刷屏的人。
- 回复别人时不提醒被回复的人。
- 代码里没有一处需要提醒身份组或全服，所以不留例外。网页发的都是 embed，embed 里的提及本来就不会提醒，不用改。

## 7. 指令可见性

### 7.1 管理指令

- 新文件 `rinbot/cogs/_perms.py`，提供 `require(**perms)`：同时加 `commands.has_permissions(**perms)`（执行时检查）和 `app_commands.default_permissions(**perms)`（Discord 默认隐藏）。56 处 `@commands.has_permissions` 全部换成它，以后不再直接用 `has_permissions`。`bot_has_permissions` 不变。
- Discord 只认顶层指令的默认权限，所以指令组的权限加在组上：
  - `/automod`、`/serverlog`：组上已经有检查，换成 `require(manage_guild=True)`。
  - `/giveaway`：组上加 `require(manage_guild=True)`。这样 `/giveaway list` 也对普通成员隐藏，前缀 `r!gw list` 也需要「管理服务器」权限。抽奖本身发在频道里，成员不需要它。
- 服务器管理员仍可在「服务器设置 → 整合 → 小凛」里调整谁能看到某条指令；已经在那里设过的服务器保留原设置。执行时仍按 `require` 里的权限检查，所以给没有对应权限的身份组放开，只会让他们看到，点了仍被拒（和现在一样）。

### 7.2 开发和主人指令

- `_perms.py` 再提供 `owner_only()`：加 `commands.is_owner()`；配置了 `DEV_GUILD_ID` 时加 `app_commands.guilds(DEV_GUILD_ID)`，斜杠版只注册到开发服务器；并给指令打上"主人指令"标记。
- 用在 hot_update、load、unload、extensions、sync、setstatus、resetstatus、setbio 上。eval 本来就只有前缀版，也换成 `owner_only()` 以带上标记。
- `DEV_GUILD_ID` 没配（为 0）时，这些指令只保留 `r!` 前缀版，不注册斜杠版。
- 前缀版 `r!hot_update`、`r!sync` 等在任何服务器都能用（仍只限主人），开发服务器出问题时可以靠它。
- `/help` 和 `health.py` 的指令列表跳过带"主人指令"标记的指令。

### 7.3 同步

`/sync` 和 `/hot_update` 的同步改成共用一个函数：

- `global`：同步全局指令，再同步开发服务器。
- `guild`：先清掉当前服务器里残留的旧副本（当前服务器是开发服务器时跳过这一步，否则会把开发指令清掉），再同步全局和开发服务器。
- `clear_guild`：在开发服务器里执行时拒绝，提示改用 `global`；其他服务器照旧。

## 8. 报错和拦截

### 8.1 文案

全部用模板发、只给本人看（第 4.4 节的 `send(private=True)`）。冷却、维护、停用用注意黄，其余用失败红。

| 情况 | 标题 | 正文 |
| --- | --- | --- |
| 成员缺权限 | 你没有权限使用这条指令 | 需要「封禁成员」权限。 |
| 小凛缺权限 | 小凛缺少「管理消息」权限 | 请服务器管理员在 服务器设置 → 身份组 里给小凛打开这个权限，再试一次。 |
| 缺参数 | 缺少参数「reason」 | 用法：`r!kick <member> [reason]` |
| 参数格式不对 | 参数格式不对 | 用法：`/kick <member> [reason]` |
| 冷却中 | 操作太快了 | {相对时间}可以再用。（用 Discord 时间戳 `<t:…:R>`，会自己倒数） |
| 只能在服务器用 | 这条指令只能在服务器里用 | （无） |
| 找不到成员或用户 | 找不到这个成员 / 找不到这个用户 | 检查一下有没有打错，或者直接 @ 对方。 |
| 找不到身份组 | 找不到这个身份组 | 检查一下名字有没有打错，或者直接 @ 这个身份组。 |
| 找不到频道 | 找不到这个频道 | 检查一下名字有没有打错，或者直接 # 这个频道。 |
| 未知错误 | 这条指令没有执行成功 | 已自动记录，错误编号 `AB12CD34`。稍后再试；一直出错的话，反馈时带上这个编号。 |
| 维护模式 | 小凛正在维护 | 网页里填的维护说明；没填时"暂时用不了，请稍后再试。" |
| 指令被全局停用 | 这条指令已停用 | 机器人主人暂时关闭了这条指令。 |
| 黑名单 | （指令：照旧不回复） | 按钮和菜单：标题"你现在不能使用这个功能"，无正文 |
| 不是主人 | 只有机器人主人能用这条指令 | （无） |

- 缺几个权限就列几个：「管理消息」「嵌入链接」。
- 用法行：斜杠调用写 `/指令名`，前缀调用写 `r!指令名`，后面按顺序列参数，必填写 `<名字>`、可选写 `[名字]`，不显示默认值。参数名暂时是英文，子项目二改中文。
- 按钮和菜单被维护或停用拦下时，用和指令一样的标题和正文。

### 8.2 权限中文名

`errors.py` 里放一张权限英文名到中文名的表，用 Discord 简体中文客户端里的叫法，实现时逐个对照客户端核对。至少包含代码里用到的：

管理员、查看频道、管理频道、管理身份组、管理服务器、踢出成员、封禁成员、禁言成员、管理消息、管理昵称、发送消息、嵌入链接、附加文件、阅读消息历史记录、添加反应、使用外部表情符号、提及 @everyone、@here 和所有身份组、连接、说话。

表里没有的权限，把英文名的下划线换成空格显示。

### 8.3 保持不变

- 未知错误的上报流程（`BotLog.report_exception`、错误编号、开发服务器收完整报错）不变，只改给用户看的文字。
- 黑名单用户用指令时照旧不回复。

## 9. `/status` 和 `/help`

### 9.1 `/status`

- 标题"小凛的运行状态"，信息色。
- 三个并排字段：延迟（"41 毫秒"）、上次启动（Discord 相对时间 `<t:启动时间:R>`）、服务器（"6 个"）。
- 去掉 CPU、内存、磁盘、操作系统和"请求者"页脚。`general.py` 不再导入 `psutil` 和 `platform`；`psutil` 没有别处在用，从 `requirements.txt` 删掉（部署脚本会因此跑一次 pip install）。
- 指令说明改成"查看小凛的运行状态"。

### 9.2 `/help`

- 斜杠调用私密回复。前缀调用没法私密，就照旧发在频道里，但只有发起人能操作菜单；别人点时私密回复"这个菜单是 {发起人} 打开的，你可以自己输入 /help"。
- 按发起人的权限过滤：指令（组内子指令看所在的组）设了默认权限、而发起人在这个服务器里没有全部这些权限时，不列出；带"主人指令"标记的指令谁都不列。私信里只列不需要权限的指令。
- 某个模块过滤后一条都不剩，就不出现在菜单和首页里（现在已经这样处理被停用的指令）。
- 首页标题"小凛 RinBot 指令中心"，保留颜文字；模块列表去掉每行的 emoji，下拉选项保留 emoji 图标。

## 10. 上线步骤

1. 推送到 GitHub 和服务器，部署脚本打印 DEPLOY OK。
2. 用户在开发服务器发 `r!sync global`（前缀版在同步前就能用）：全局指令去掉 8 条开发和主人指令并带上默认权限，开发服务器拿到这 8 条斜杠指令。

## 11. 测试

根目录 `tests/`，沿用 pytest 和现有的 AST 扫描写法（参考 `test_guild_only.py`）。

- **模板**（`rincore.embeds`）：五种颜色的值；未知种类报错；各部分截断到上限并以"…"结尾；总字数超 6000 时截正文；空字段跳过；只有传了时间才有时间戳；`event_kind` 覆盖第 4.1 节表里每个事件。
- **抽奖消息**：三种状态的标题、颜色、字段；没有发起人或没有身份组限制时不出现对应字段；机器人和网页调用同一个函数（AST 扫描 `giveaway.py` 和 `routes.py` 里不再拼抽奖 embed）。
- **不再自己写颜色**：扫描 `rinbot/cogs/`（除 `netease.py`）和 `website/routes.py`，不再出现 `discord.Color.` / `discord.Colour.` / `color=0x…` / `"color": 0x…`。
- **权限**：`require()` 本身同时加上执行时检查和默认权限（单元测试）；扫描 cogs，`commands.has_permissions` 只出现在 `_perms.py`；指令组里只要有一个子指令用了 `require`，组本身也必须用 `require`，且组的权限覆盖子指令要的权限。
- **主人指令**：`owner_only()` 在配置了开发服务器时只把斜杠版注册到开发服务器，`DEV_GUILD_ID` 为 0 时不注册斜杠版（单元测试）；扫描 cogs，`commands.is_owner` 只出现在 `_perms.py`，8 条开发和主人指令都用了 `owner_only()`；`/help` 和 `health.py` 的列表里都没有带标记的指令。
- **动作中文名**：`cases.ACTION_NAMES` 和 `website/i18n/zh.json` 的 `moderation.action` 完全一致。
- **同步**：用假的 tree 检查三种 scope 的调用顺序，开发服务器里执行 `guild` 不会清掉开发指令，执行 `clear_guild` 被拒。

## 12. 风险

- **默认权限需要一次同步才生效。** 没跑第 10 节第 2 步之前，/ 列表还是旧的。旧的全局开发指令在同步前点了会提示指令不存在，不会执行任何操作。
- **权限中文名可能和客户端不完全一致。** Discord 改过几次权限的叫法（比如"踢出成员"在新版里可能写成更长的名字）。实现时以客户端为准，写错的代价只是一个词不一样。
- **旧消息不会自己变。** 已经发出的抽奖、身份组面板、日志保持旧样子，直到机器人编辑它们。
- **默认隐藏只管显示**，执行时检查仍在，所以就算 Discord 端的隐藏没生效或被服务器改掉，没权限的人也执行不了。

# 等级设置

日期：2026-11-09 · 状态：设计已确认，待审阅

## 1. 目标

等级系统现在对所有服务器一视同仁：一定加经验，升级提示一定发在原频道，控制台的等级页只有一张排行榜。管理员想关掉、想把提示挪走、想用等级奖励身份组，都做不到。

这一轮给等级页加上三项设置：总开关、升级提示去向、等级奖励。

完成标准：

- 没有动过设置的服务器，行为和现在完全一样。
- 第 3 到第 9 节列出的每一项都实现，页面在浅色、深色、375px 手机宽度下都正常。
- `python -m pytest -q`、`cd website && python -m pytest -q tests`、`cd website && node --test tests/*.cjs` 全部通过，包括第 10 节新增的测试。
- 不自动部署，部署时机由用户决定。

## 2. 范围

**修改：**

- 机器人：`rinbot/cogs/leveling.py`、`rinbot/rincore/sync.py`、`rinbot/rincore/guild_cleanup.py`
- 网页后端：`website/routes.py`、`website/permcheck.py`
- 网页前端：`website/templates/server.html`、`website/static/js/modules/leveling.js`、`website/static/js/modules/overview.js`（概览开关和摘要）、`website/static/css/console.css`、`website/i18n/zh.json`
- 测试：见第 10 节；README 的测试数徽章随之更新

**不做：**

- 自定义升级提示文案，在提示里写出获得的身份组。
- 调整经验速度和冷却时间，按频道或身份组禁止获得经验。
- 一个等级配多个身份组，升到高等级时摘掉低等级奖励。
- 收回已发出的身份组。
- `_validate_guild_resources` 的层级判断不重构，继续给其他模块用。

## 4. 行为规则

### 总开关

- 没有配置行的服务器视为开启。
- 关闭后不加经验、不发提示、不发奖励。已有等级保留，`/rank`、`/leaderboard` 和控制台排行榜照常可用。

### 升级提示

- 去向三选一：`here` 原频道、`channel` 指定频道、`off` 不发。
- 文案不变：`🎉 恭喜 **{成员提及}**！你升级到了 **Level {等级}**！✨`。
- 指定频道被删除或小凛无权发言时，这条提示不发，也不改发到原频道。经验和奖励不受影响。

### 等级奖励

- 每条奖励是一个等级和一个身份组。一个等级只能配一个身份组，同一身份组不能配给两个等级。最多 20 条，等级范围 1 到 999。
- 奖励累积保留。
- 成员每次获得经验后检查（受现有 60 秒冷却限制），已达到等级却缺少的身份组都发放。这同时覆盖刚升级的成员和设置奖励前就已达到等级的成员。
- 没有缺少的身份组时，不调用 Discord。
- 手动摘掉的身份组，会在该成员下次获得经验时发回，页面已写明。
- 删除一条奖励后，已发出的身份组不收回。
- 小凛给不了的身份组（排在小凛最高身份组之上或相同位置，或者是托管身份组）可以保存，发放时跳过，不调用 Discord。不拦保存，因为身份组顺序会变，否则一条失效的奖励会让整页都存不了。
- 小凛没有“管理身份组”权限时，全部奖励跳过。

## 5. 存储

`leveling.db` 新增一张表，机器人的 `cog_load` 和网页的 `ensure_tables` 都用 `CREATE TABLE IF NOT EXISTS` 创建，不依赖启动顺序。

```sql
CREATE TABLE IF NOT EXISTS level_config (
    guild_id INTEGER PRIMARY KEY,
    enabled INTEGER DEFAULT 1,
    notify_mode TEXT DEFAULT 'here',
    notify_channel INTEGER DEFAULT 0,
    rewards TEXT DEFAULT '[]'
)
```

- `rewards` 是 JSON 数组，按等级升序：`[{"level": 5, "role_id": "123456"}]`。`role_id` 用字符串，避免浏览器丢失大整数精度。
- 设置和奖励在同一行，一次保存整体生效。
- `notify_mode` 不是 `channel` 时，`notify_channel` 写 0。这样隐藏的旧频道被删除时不会挡住保存。
- `rincore/guild_cleanup.py` 的 `GUILD_TABLES` 增加 `("leveling", "level_config")`。

## 6. 机器人端

`cogs/leveling.py`：

- `cog_load` 建表，把全部配置读入内存，并注册 `change_watcher.register("leveling", self.reload_guild)`；`cog_unload` 注销。写法和 `cogs/musicconfig.py` 相同。
- `rincore/sync.py` 的 `MODULES` 增加 `"leveling"`。不加的话 `notify()` 会拒绝这个模块，网页保存后机器人不重载。
- `reload_guild(guild_id)` 只重读这一行，没有配置行时清掉缓存。
- `get_config(guild_id)` 读内存，未配置的服务器返回默认值。
- `rewards` 解析失败时按空列表处理并记日志，不影响加经验。

`on_message` 的顺序：

1. 现有的机器人和私信过滤。
2. 读配置，关闭就返回，不写冷却、不访问数据库。
3. 现有的冷却和加经验逻辑，先提交数据库。
4. 升级时发提示，失败只记日志。
5. 作者是 `discord.Member` 时发放缺少的奖励，失败只记日志。

第 4、5 步互不影响，任何一步失败都不丢经验。

把判断逻辑抽成不依赖 Discord 的函数，便于测试：

- `parse_rewards(raw) -> list[tuple[int, int]]`：解析存储内容，得到 `(等级, 身份组 id)`，非法内容返回空列表。
- `due_role_ids(rewards, level, owned_ids) -> list[int]`：返回已达到等级且尚未拥有的身份组 id。

发放前的过滤规则和 `welcome.py` 的自动身份组一致：`guild.me.guild_permissions.manage_roles` 为真，且身份组存在、不是托管身份组、低于 `guild.me.top_role`。过滤后为空就不调用 Discord。

## 7. 接口

沿用 `check_guild_access`，未授权返回 401。

### `GET /api/guild/<gid>/leveling`

```json
{
  "enabled": true,
  "notify_mode": "here",
  "notify_channel": "0",
  "rewards": [{"level": 5, "role_id": "123456"}],
  "blocked_roles": {"456789": "above", "789012": "managed"},
  "can_manage_roles": true
}
```

- 没有配置行时返回默认值，不写库。
- `blocked_roles` 覆盖服务器里所有小凛给不了的身份组，不只是已配置的，页面选中时才能立刻提示。`@everyone` 不包含在内。
- `permcheck.py` 新增纯函数 `role_limits(roles, bot_member, guild_id) -> {"can_manage_roles": bool, "blocked": {id: reason}}`。权限计算沿用 `base_permissions`，`ADMINISTRATOR` 视为有权限，托管身份组的原因优先记为 `managed`。
- 读不到 Discord 时，`blocked_roles` 为 `{}`，`can_manage_roles` 为 `null`，页面不显示任何警告。

### `POST /api/guild/<gid>/leveling`

请求体是整份配置：`enabled`、`notify_mode`、`notify_channel`、`rewards`。校验如下，不通过返回 400 和中文错误信息：

- 请求体是对象，`enabled` 是布尔值。
- `notify_mode` 是 `here`、`channel`、`off` 之一；选 `channel` 时必须有频道。
- `rewards` 是数组，不超过 20 条。
- 每条的 `level` 是 1 到 999 的整数，布尔值和小数都不算；`role_id` 是纯数字字符串。
- 等级和身份组都不重复。
- `enabled` 为真时，用 `_validate_guild_resources` 确认频道和身份组属于该服务器，不传 `assignable_roles`。返回 `False` 时给 400，返回 `None`（读不到 Discord）时给 502 且不写库。`enabled` 为假时跳过这一步，见第 8 节。

通过后按等级升序写入，调用 `_notify_bot("leveling", g)`，并记审计日志。

### 概览页

- `_TOGGLE_TABLES` 增加 `"leveling": ("DB_LEVELING", "level_config")`，模板的 `toggle_slugs` 增加 `leveling`。
- `_ENABLED_WITHOUT_ROW` 增加 `"leveling": 1`。
- `_SUMMARY_SPECS` 增加 `leveling`，摘要包含 `enabled` 和奖励数量；有奖励时显示“{n} 个等级奖励”。
- `_guild_module_config` 增加 `leveling`：没有配置行或数据库文件时返回 `enabled`，因为它实际在运行；有配置行时按 `enabled` 返回 `enabled` 或 `disabled`。

## 8. 页面校验

保存前在前端校验，出错时错误显示在对应行下方，并滚动到第一处错误。

- 选了“发到指定频道”但没选频道。
- 某行没选身份组，或等级不在 1 到 999。
- 等级重复或身份组重复。
- 身份组已不存在。

小凛给不了的身份组只警告，不阻止保存。

总开关关闭时，奖励行不可编辑，所以已删除的频道和身份组不再挡住保存，已存的 id 原样提交，否则管理员会因为一条失效的奖励而关不掉等级系统。其余校验照常。

## 9. 出错处理

| 情况 | 结果 |
|---|---|
| 打开页面时读不到 Discord | 设置照常显示，不显示任何警告。已存的身份组保留在下拉框里，显示为“未知身份组”，不判定为已删除 |
| 保存时读不到 Discord | 不写库，提示稍后再试，未保存状态保留 |
| 之前选的频道已被删除 | 下拉框回到未选状态，要重新选才能保存 |
| 奖励里的身份组已被删除 | 该行提示“已不存在”，要换一个或删掉才能保存；机器人端直接跳过 |
| 发提示时 Discord 报错 | 记日志，不影响经验和奖励 |
| 发身份组时 Discord 报错 | 记日志，不影响经验和提示，下次获得经验时再检查 |
| 存储内容损坏 | 机器人按无奖励运行并记日志 |

## 11. 设计取舍

- **用标签而不是上下排列**：排行榜最多 15 行，放在设置下面会把页面拉得很长；分开后未保存提示只和设置有关。
- **奖励存在 JSON 列而不是单独的表**：只有整份读写，没有按奖励查询的场景；同一行还能保证保存的原子性。
- **下次获得经验时补发，而不是保存后批量发放**：批量发放要遍历成员，大服务器会撞 Discord 速率限制。代价是不活跃的成员要等到下次发言。

日期：2026-11-04
前一版：`2026-11-04-bot-messages-foundation-design.md`（子项目一：消息模板、提醒和指令可见性，已上线，bc6146e）

## 1. 目标

用户希望所有指令用起来顺手，做法参考 Dyno、Carl-bot、MEE6、ProBot 这些大型机器人。它们的共同点是：常用的管理动作是平铺的单条指令；处罚记录围绕案件编号来管；设置主要放在控制台；一组相关的管理指令收进一个组。

这一版要做到：
- 顶层斜杠指令从 66 条降到 38 条，和控制台重复的设置指令交给控制台。
- 指令名统一英文；参数名、说明、选项按用户客户端语言显示中文或英文。
- 编号、存档名、队列位置这类参数都能从列表里选，不用手打。
- 时长只有一种写法，中文单位也能用；数字在 Discord 输入框里就被限制在范围内。
- 有 `/case` 可以查看和修改案件，`/help 指令` 能查单条指令的用法。

成功标准：
- 全部测试通过，部署脚本打印 DEPLOY OK。
- 用户在开发服务器跑过 `r!sync global` 后检查：中文客户端里新指令的参数显示中文，`/unban`、`/giveaway end`、`/case view` 能从列表里选，`/mute` 的时长有候选，旧的 `r!warns`、`r!tempban` 还能用，`r!welcome_image` 会回复"已移到控制台"。

## 2. 现在的问题（读代码统计）

1. **顶层指令多。** 66 条普通指令加 8 条开发指令，另有 2 条本地的网易云指令，离 Discord 的 100 条上限不远。迎新拆成 10 条 `welcome_*`，身份组 6 条 `rr_*`，警告散在 warn、warns、delwarn、clearwarns、warn_config 五处。
2. **参数没有说明。** 只有 play、search、queue、volume 用了 `@app_commands.describe`。另外 16 条在 docstring 里写了说明，但写法 discord.py 读不到（没有缩进的 `名字: 说明`），所以 Discord 里显示"…"。参数名全是英文。
3. **要手打编号。** 13 条指令要填 ID、存档名或位置：`/giveaway end|reroll`（抽奖 ID）、`/delwarn`（警告 ID）、`/unban`（用户 ID）、`rr_*` 四条（消息 ID，要开开发者模式才能复制）、`loadq`、`delqueue`、`/toggle`、`/remove`、`/move`。
4. **时长三种写法。** tempban、mute、抽奖填 `1h30m`；`automod mute_duration` 和 `warn_config` 填分钟数；`slowmode` 填秒数。解析器只认 d、h、m、s，不支持周和中文。
5. **选项是英文、范围靠事后检查。** automod、serverlog、`/loop` 的选项是英文；`welcome_message` 要手打 `welcome` 或 `farewell`；中奖人数、清理条数、慢速秒数发出去以后才提示超范围。
6. **封禁分两条、案件改不了。** `/ban` 和 `/tempban` 是两条指令；原因写错了没法改，也没法单独查看一个案件。
7. **和控制台重复。** 迎新 10 条、自动审核 9 条、审计日志 7 条、身份组 6 条、`modlog_channel`、`warn_config`，控制台都能做。

### 4.3 兼容旧用法

- **改了名的指令保留旧前缀名。** 新建 `cogs/legacy.py`，用隐藏的纯前缀指令转给新指令，参数顺序和以前一样：`r!tempban`（转 `/ban`，时长必填）、`r!warns`、`r!delwarn`、`r!clearwarns`、`r!modlog`、`r!saveq`、`r!loadq`、`r!queues`、`r!delqueue`、`r!toggle`（停用和启用来回切换，和以前一样）、`r!togglelist`、`r!welcome_setup`、`r!welcome_test`、`r!automod_words`、`r!automod_whitelist`、`r!automod_ignore`（第一个参数是 add / remove / list）。这些指令不进斜杠列表，也不占 100 条的名额。转发前先跑新指令的全部检查（权限、每个服务器的停用状态、全局停用和维护），不通过时的提示和直接用新指令一样；不能用 `ctx.invoke` 直接转，因为它会跳过这些检查。
- **删掉的指令回复去向。** 有人打 4.2 表里的旧名字时，`errors.py` 在"找不到指令"的分支里认出它，私密回复 `("info", "这项设置已移到控制台", "在控制台的「{页面名}」里修改。")`，附一个链接按钮"打开控制台"，指向 `https://rin-bot.com/dashboard/server/{服务器 ID}#{页面}`。不在表里的名字照旧不回复。
- **停用记录迁移。** 机器人加载时把每个服务器的停用记录和全局停用记录里的旧名字换成新名字，并且只迁移一次：
  - `warns`、`delwarn`、`clearwarns` → `warnings`；`modlog` → `case`；`saveq`、`loadq`、`queues`、`delqueue` → `playlist`；`toggle`、`togglelist` → `commands`；`welcome_setup`、`welcome_test` → `welcome`；`automod_words`、`automod_whitelist`、`automod_ignore` → `automod`。
  - 多个旧名字指向同一个新名字时，只要有一个停用了，新指令就停用。
  - `tempban` 的记录删掉：它并进了 `/ban`，不能单独停用；为了不把 `/ban` 也停掉，不做合并。
  - 4.2 表里删掉的指令，记录直接删掉。

## 5. 中英双语

### 5.1 规则

- 指令名和子指令名：英文，所有语言都一样。
- 参数名、参数说明、指令说明、选项名：代码里写英文（Discord 的默认值），简体中文（`zh-CN`）和繁体中文（`zh-TW`）客户端显示同一份简体中文。
- 英文写法：说明用一句话、句首大写、不加句号，参数名小写单词（`member`、`duration`、`reason`）。
- 中文写法：参数名用 2–4 个字的名词（成员、时长、原因、条数）；说明一句话说清楚做什么，可选参数写上默认值（"默认 10 分钟"）。
- 长度：名字最多 32 个字符，说明最多 100 个字符，中英文都一样。

### 5.2 翻译表

- 新文件 `rinbot/i18n/commands.zh.json`，按指令路径组织，例如 `ban`、`warnings remove`、`automod words add`。每条记中文说明、每个参数的中文名和说明、每个选项的中文名，以及 `/help` 用的一两个例子。
- 新建 `rinbot/rincore/command_i18n.py`：读这张表，提供 `zh(path)` 查说明和例子。再提供一个 discord.py 的 `app_commands.Translator` 子类，同步指令时按位置（指令说明、参数名、参数说明、选项名）返回中文；表里没有的返回 `None`，Discord 就显示英文。机器人在 `setup_hook` 里装上这个翻译器。
- `/help` 和 `health.py` 导出的指令列表（控制台用）改从这张表取中文说明，表里没有时退回英文。
- 自动补全的候选文字（第 6.2 节）按交互的语言显示：中文客户端显示中文，其他显示英文。

## 6. 参数怎么填

### 6.1 时长

- `rincore/durations.parse_duration` 扩展：
  - 单位：`s`、`m`、`h`、`d`、`w`，以及中文 秒、分、分钟、时、小时、天、日、周、星期。
  - 允许组合和空格：`1h30m`、`1 小时 30 分钟`、`2天`，不区分大小写。
  - 同一单位不能重复，总时长要大于 0。
- 每条指令的常用值和上限：

| 指令 | 常用值 | 上限 | 说明 |
| --- | --- | --- | --- |
| `/mute` | 10 分钟、1 小时、1 天、7 天、28 天 | 28 天 | Discord 禁言最长 28 天 |
| `/ban` | 1 天、7 天、30 天 | 365 天 | 不填是永久 |
| `/giveaway start` | 1 小时、1 天、3 天、7 天 | 365 天 | |
| `/slowmode` | 关闭、5 秒、30 秒、1 分钟、5 分钟、1 小时 | 6 小时 | `0`、`关闭`、`off` 表示关闭 |
| `/case duration` | 和这个案件的动作相同 | 同左 | |

- 自动补全：
  - 输入为空时列出这条指令的常用值。
  - 只输入一个数字（如 `3`）时，列出"3 分钟、3 小时、3 天、3 周"里不超上限的。
  - 能解析时，把它规范化后放在第一个，再接常用值。
  - 候选的显示文字按语言显示（"1 小时 30 分钟" / "1 hour 30 minutes"），值是规范写法 `1h30m`。
- 填错时私密提示 `("error", "时长格式不对", "可以写 10m、1h30m、2d、1w，或者 10分钟、1小时、2天。")`；超上限时提示 `("error", "时长太长了", "最长 {上限}。")`。

### 6.2 从列表里选

每个补全最多返回 25 个候选，按输入的文字过滤（名字、内容、编号都能搜），3 秒内必须返回：

| 参数 | 候选 | 显示 | 值 |
| --- | --- | --- | --- |
| `/unban` 用户 | 服务器的封禁名单（每个服务器缓存 60 秒） | `名字（ID）` | 用户 ID |
| `/warnings remove` 警告 | 最近的警告，新的在前 | `#3 成员名 原因…` | 警告 ID |
| `/case view`、`reason` 案件 | 最近的案件 | `#12 警告 成员名 原因…` | 案件编号 |
| `/case duration` 案件 | 还在生效的禁言和临时封禁 | 同上，加"剩 X" | 案件编号 |
| `/giveaway end` 抽奖 | 进行中的 | `奖品 剩 2 小时` | 抽奖 ID |
| `/giveaway reroll` 抽奖 | 已结束的 | `奖品 已结束` | 抽奖 ID |
| `/playlist load`、`delete` 名字 | 已保存的存档 | `名字（N 首）` | 名字 |
| `/remove`、`/move` 位置 | 当前队列 | `3. 歌名` | 位置 |
| `/commands disable` 指令 | 还开着的顶层指令 | 指令名和中文说明 | 指令名 |
| `/commands enable` 指令 | 已停用的 | 同上 | 指令名 |
| `/help` 指令 | 这个人能用的指令（含子指令） | 指令路径和说明 | 指令路径 |
| `/automod words remove`、`whitelist remove` | 已有的违禁词、白名单域名 | 原文 | 原文 |

- 用户不选候选、直接打字时照常解析；找不到对应的记录时私密提示"找不到这个{东西}"，不报未知错误。
- 前缀调用没有补全，参数照旧手填。

### 6.3 选项和数字

- `/loop` 模式用选项：`off` / `single` / `queue`，中文显示 关闭 / 单曲 / 队列。
- 数字范围交给 Discord（`app_commands.Range`）：

| 参数 | 范围 |
| --- | --- |
| `/purge` 条数 | 1–500 |
| `/volume` | 0–150 |
| `/roll` 面数 | 2–1000 |
| `/giveaway start` 中奖人数 | 1–20 |
| `/ban` 删除消息天数 | 0–7 |
| `/leaderboard`、`/queue`、`/case list` 页码 | ≥ 1 |

## 7. `/case`

- **`list [成员] [页码]`**：和原来的 `/modlog` 输出一样。
- **`view 案件`**：显示一个案件，样子和管理日志里那条一样（子项目一的模板）。禁言或临时封禁还在生效时，多一个字段"剩余 X"。
- **`reason 案件 原因`**：
  - 更新案件的原因。
  - 在管理日志频道补发一条：注意黄，标题 `"案件 #12：原因已更新"`，字段"之前""之后""管理员"。
  - 回复成功提示 `("success", "案件 #12 的原因已更新")`。
  - 旧的日志消息不改，因为没有记它的消息 ID。
- **`duration 案件 时长`**：
  - 只对还在生效的禁言和临时封禁有效，其他案件私密提示 `("error", "这个案件没有可以修改的时长")`。
  - 新时长从现在算起：禁言调用 Discord 的禁言接口改到期时间，受 28 天上限限制；临时封禁改 `tempbans` 表的解封时间。
  - 更新案件的时长文字，补发一条日志 `"案件 #12：时长已更新"`，回复 `("success", "案件 #12 将在 <t:…:R> 解除")`。
  - 执行时检查权限：禁言案件要「禁言成员」，临时封禁案件要「封禁成员」；机器人也要有对应权限。
- **找不到案件**：私密提示 `("error", "找不到案件 #{编号}")`。

## 8. `/help 指令`

- 不填参数时和现在一样（私密的模块菜单）。
- 填了指令时，私密回复一张信息卡：
  - 标题：指令路径，如 `/case duration`。
  - 正文：中文说明。
  - 字段：用法、例子、需要的权限（按 Discord 中文叫法，没有就不显示）。
  - 用法行的参数用中文名：`/ban <成员> [时长] [原因]`。
- 指令不存在或这个人看不到时，私密提示 `("error", "找不到这条指令")`。

## 9. 权限规则调整

- 子项目一的测试要求"组的权限包含每个子指令的权限"。这条规则会把子指令藏起来，不让有权限用它的人看到，方向反了。改成：**每个子指令执行时要求的权限，必须包含所在组的默认权限**。这样能用子指令的人一定看得到这个组；斜杠子指令也不会因为 discord.py 不跑组上的检查而没有检查。
- 按新规则：
  - `/giveaway list` 加上「管理服务器」（顺带修掉子项目一的遗留问题）。
  - `/warnings` 组是「管理消息」，`clear` 另外要求「管理服务器」。
  - `/case` 组是「管理消息」。
  - `/automod`、`/welcome`、`/commands` 组是「管理服务器」。
  - `/playlist` 组不需要权限。

## 10. 控制台

- `health.py` 导出的指令列表：
  - 说明改用翻译表里的中文。
  - 删掉的指令自然消失。
  - 指令开关页按新的顶层指令显示。
- 写死旧指令名的文案跟着改：
  - 主页功能介绍里的 `/tempban` → `/ban`；
  - 控制台指令页和 `routes.py` 里的 `/toggle` → `/commands`；
  - 机器人里提到 `/rr_add`、`/serverlog …`、`/automod enable`、`/saveq`、`/queues`、`/welcome_setup` 的提示文字，改成新指令名或"在控制台里修改"。

1. 推送并部署，部署脚本打印 DEPLOY OK。

## 13. 风险

- **旧斜杠名失效。** 习惯 `/welcome_setup`、`/warns` 的人在 / 列表里找不到旧名字，要改用新名字。前缀旧名还能用，`/help` 能搜到新指令。
- **服务器自定义过的指令权限会丢。** 有些服务器可能在「整合」里给 `/warns` 这类旧指令单独设过谁能用。改名后 Discord 把新指令当成新的，这些设置不会带过去，要重新设。
- **繁体中文客户端看到简体。** 这次不单独做繁体。
- **补全依赖数据库和 Discord 的速度。** 封禁名单太大时，第一次拉取可能接近 3 秒。缓存 60 秒以后会快；超时时 Discord 显示没有候选，用户仍可直接输入 ID。
- **`/case duration` 改不了旧的日志消息**，只能补发一条更新记录。

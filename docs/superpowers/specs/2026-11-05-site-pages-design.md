## 1. 目标

官网现在只有首页。准备邀请小凛的管理员想知道"有哪些指令""要给哪些权限""数据怎么处理"，都没有地方看；输错网址会落到框架默认的 404。

这一批给官网加五个页面，只改网站，不改 bot：

| 路径 | 页面 | 给谁看 |
|---|---|---|
| `/commands` | 指令大全 | 管理员和成员：找指令、看怎么填、谁能用 |
| `/permissions` | 邀请权限说明 | 邀请前的管理员，以及排查"小凛为什么做不了"的管理员 |
| `/privacy` | 隐私政策 | 所有人；开发者后台和申请验证时要填 |
| `/terms` | 服务条款 | 同上 |
| 任意不存在的地址 | 404 | 输错网址的人 |

完成标准：

- 用户在本地试用后认可。
- 五个页面中英可切换，跟随日夜间设置，375px 宽没有横向滚动。
- `pytest` 和 `node --test website/tests/` 全部通过，包括本 spec 新增的测试。
- 首页现有测试全部通过（改为读取公共样式表的那几条除外，见 9.1），渲染出来和改之前一样，只多了第 3.3 节列出的链接。
- 不部署；部署时机由用户决定。

## 4. 路由

- `GET /commands`、`/permissions`、`/privacy`、`/terms`：渲染对应模板，传入 `is_logged_in`（控制台按钮文案用，取法同首页）。
- 全局 `@app.errorhandler(404)`：
  - 路径以 `/api/` 开头：返回 `{"error": "not found"}`，状态码 404，和现有接口一致。
  - 其他：渲染 `not_found.html`，状态码 404。传入请求路径（截到 80 个字符，模板自动转义）和建议页面：用 `difflib.get_close_matches` 把去掉首尾 `/`、转小写的路径和 `["commands", "permissions", "privacy", "terms", "dashboard"]` 比较，`cutoff=0.6`，有结果就给出一个。
- `invite_url`：`website/site_data.py` 提供 `invite_url(permissions=INVITE_PERMISSIONS)`，路由初始化时把结果放进 `app.jinja_env.globals`。首页原来的 `{% set invite_url = … %}` 删除，生成的链接和现在逐字相同。

## 5. 指令大全 `/commands`

### 5.1 数据

`website/tools/build_commands.py`（在仓库根目录运行 `python website/tools/build_commands.py`）：

- 不启动 bot，按 `tests/command_tree.py` 的办法导入 `rinbot/cogs/` 下的 cog 类（跳过 `netease.py` 和主人指令），遍历每条顶层斜杠指令和它的子指令，只收叶子指令。
- 合并 `rinbot/i18n/commands.zh.json` 的中文说明、参数中文名和说明、例子。
- 写出 `website/data/commands.json`，键按固定顺序排列、`ensure_ascii=False`、两格缩进，方便看 diff：

```json
{"commands": [
  {"name": "ban", "id": "ban", "group": "Moderation",
   "en": "Ban a member; add a duration for a temporary ban",
   "zh": "封禁一名成员，填了时长就是临时封禁",
   "perms": ["ban_members"],
   "params": [{"name": "member", "required": true, "en": "…", "zh": "成员", "zh_desc": "…"}],
   "examples": ["/ban @小明 7d 刷屏"]}
]}
```

- `group`：cog 名，`CommandToggle` 和 `Help` 归到 `System`。`id`：指令名里的空格换成 `-`，用作 `#锚点`。
- `perms`：顶层指令的 `default_permissions` 里为真的权限名。
- 现在是 10 组、68 条叶子指令（第 1 段设计时说的"40 条"是顶层数，子指令展开后是 68 条）。`/netease` 只在线上，不列。

网站启动时读一次这个文件。分组（顺序、中英显示名、一句介绍、对应的控制台页面和它在控制台里的名字）写在 `site_data.COMMAND_GROUPS`，取值见试装页的 `GROUPS`。权限显示名写在 `site_data.PERM_LABELS`，用 Discord 自己的中文叫法：管理服务器、踢出成员、封禁成员、禁言成员、管理消息、管理频道、管理身份组。

页面把这三份数据（指令、分组、权限显示名）放进一个 `<script type="application/json" id="commands-data">`，`commands.js` 从这里读，用来搜索和画详情栏。

### 5.2 视觉方案（frontend-design）

- **配色**：沿用 `site.css` 的 token。樱粉只给能点的和选中的东西（选中行的底色和左边条、输入框预览里当前参数的描边、链接、按钮）；搜索框里的 `/` 用灰色。Discord 的灰只出现在输入框预览里。
- **字号**：只用 12.5 / 14 / 15 / 19 / 24 / 40px；输入框 16px（防止手机聚焦时放大）；手机上的页面标题 32px；导航品牌沿用首页的 18px。
- **字体**：Fredoka 600 用于页面标题、分组标题、详情里的指令名；其余用系统中文字体。不用等宽字体。
- **版式**：左对齐。左边是列表，`minmax(0, 1fr)`；右边是 360px 的详情栏，间隔 48px，`position: sticky; top: 88px`，高度超过屏幕时在栏内滚动。
- **原则**：整页只有输入框预览一处显眼；动效只回应操作（参数描边的 0.12s 过渡）；小凛只在"没有结果"时出现。

```

在 Discord 里输入 / 就能用。点一条指令，看它在输入框里怎么填。
```

### 5.3 列表

- 每组：标题（分组名 + 条数）、一句介绍；整组指令要求同一个权限时，介绍后面加"这一组默认需要 X 权限"，行里就不再标；权限各不相同的组（管理）在每行右边标"需要 X"。
- 每行三列，所有分组共用同一套列宽（列表容器是 grid，分组和行用 `subgrid`），说明文字从同一条竖线开始：指令名、说明（单行，超出显示省略号，完整内容放 `title`）、权限。
- 子指令写成灰色的前缀加黑色的后半段：`/automod` `whitelist add`。
- 列表由服务器渲染，中英两份用 `data-l` 切换。没有 JS 时完整列表照样可读，只是没有详情和搜索。

### 5.4 详情栏

从上到下：

1. 指令名（Fredoka 24px）和说明。
2. 谁能用：有默认权限时显示锁图标和"需要 X 权限"，没有时显示"所有人都能用"。
3. **输入框预览**：模仿 Discord 输入框。框里是 `/指令名` 加必填参数的槽位，可不填的收成"+N 个可不填"；上方弹出框显示当前参数的名字、必填或可不填、说明，左上角是小凛头像和名字。没有参数的指令，弹出框显示指令本身。
4. 参数列表：每个参数是一个按钮（名字、必填或可不填、说明），`title` 是"在上面的输入框里看它的位置"。鼠标移上去或点一下，预览里对应的槽位描边；选的是可不填的参数，就把它加进框里。
5. 例子：纯文字行，左边一条细线。英文模式下，带中日韩文字的例子不显示。
6. 「复制 /ban」按钮：只复制指令名，提示"已复制 /ban，在 Discord 里粘贴后选中它"。例子不做成复制按钮，因为整句粘进 Discord 不一定会被识别成指令。
7. 有对应控制台页面的分组，显示"在控制台的「X」里也能设置"，链到 `/dashboard`。
8. 有默认权限时，最后一行写"想让更多人或更少人能用，在 Discord 的「服务器设置 › 整合 › 小凛」里改"。

1080px 以下没有右侧详情栏，详情展开在选中那一行的下面，内容一样（不重复指令名和说明）。

### 5.5 交互

- 搜索匹配指令名、中英说明、参数名和参数说明，不区分大小写，忽略开头的 `/`。不匹配的行和空分组隐藏；匹配的文字用 `<mark>` 标出（只处理当前语言的 span，原文存在 `data-text` 里，清空时还原）；搜索框下面显示"找到 N 条"，用 `role="status"` 播报。
- 没有结果：小凛的"诶?"贴纸（`confused-480.webp`，88px），"没有和「X」有关的指令。试试功能名："，后面四个按钮（音乐、封禁、欢迎、抽奖，英文模式下是英文），点了就用这个词搜。
- 键盘：页面上按 `/` 聚焦搜索框；搜索框里按 Enter 选中第一条、Esc 清空；焦点在搜索框或列表行上时，上下方向键在可见的行之间移动选中项。
- 选中一条时地址改成 `#id`（`history.replaceState`）；带 `#id` 打开页面时选中这一条并滚到中间；没有 `#id` 时选中第一条。点侧栏的分组链接跳到分组，不改选中项。
- 列表用 `role="listbox"`，行是 `role="option"` 的按钮，选中项 `aria-selected="true"`；详情栏 `aria-live="polite"`。
- 切换语言时（`rin:lang` 事件）重画详情栏和"找到 N 条"。

## 6. 邀请权限 `/permissions`

### 6.1 数据：`website/site_data.py`

- `CLIENT_ID = 1352551616427069492`、`INVITE_PERMISSIONS = 1374694796438`、`invite_url(permissions)`。
- `PERMISSIONS`：16 项，每项是位号、分组、中英名称、中英用途、中英"取消后"。分组、名称、用途、后果的取值见试装页 `GROUPS`，全部已和代码核对（例如 `/lock` 改频道权限覆盖要用到"管理身份组"；服务器日志查审核日志来写执行人）。名称用 Discord 自己的中文叫法：查看频道、发送消息、在子区中发送消息、嵌入链接、附加文件、阅读消息历史、连接、说话、使用语音活动、管理身份组、管理消息、管理频道、踢出成员、封禁成员、禁言成员、查看审核日志。
- `NEVER`：管理员、管理服务器、提及 @everyone、管理 Webhook，各一句原因。

### 6.2 页面

- 标题"邀请小凛时要的权限"，一段说明：点邀请后 Discord 会列出这 16 项；每项写了用途；可以取消勾选，这里会说哪些功能会受影响。
- **勾选列表**（整页唯一显眼的地方）：Discord 邀请页式的卡片，顶部小凛头像和"小凛 想在你的服务器里获得这些权限"，小字"和 Discord 邀请页上的一样，顺序可能不同"。五组：发消息、放歌、身份组、管理和自动审核、服务器日志。每项一个复选框、名称、用途。
  - 勾选的框用正文色填充，不用樱粉。16 个粉色方块会把视线从邀请按钮上抢走，取消勾选后出现的橙色提示才应该是最显眼的。
  - 取消勾选：名称加删除线，下面出现橙色的"取消后：…"（`--warn` 字、`--warn-soft` 底）。这一步用 CSS `:has(input:not(:checked))` 完成，不依赖 JS。
- **右侧栏**（1080px 以下排在列表后面）：
  - 全部勾选时显示"全部勾选，所有功能都能用"，提示"试着取消一项，看看会少什么"。
  - 有取消时显示"取消了 N 项"和每项的后果，一个"全部勾回"按钮。
  - 邀请按钮：链接里的 `permissions` 按当前勾选的位计算（`BigInt`），全部勾选时和 `invite_url` 完全相同；有取消时文案改成"按这里的勾选邀请小凛"。
  - 小字："Discord 的邀请页上也能取消勾选，效果一样。"
- **邀请之后：把小凛的身份组往上拖**（`id="role-order"`）：一句规则（机器人只能发放、处罚比自己低的身份组和成员），一句做法（服务器设置 › 身份组，把小凛拖到要发放的身份组上面），一句提醒（管理员的身份组可以留在上面）；右边一个示意的身份组列表，小凛那一行高亮，标"放在这里"。
- **小凛不会要的权限**：平铺列表，四项各一句。
- 没有 JS 时：勾选列表和取消后的提示照常工作，右侧栏只显示默认的邀请按钮。

## 7. 隐私政策 `/privacy` 和服务条款 `/terms`

### 7.1 版式（frontend-design）

- 阅读页：单栏，正文宽 38em（约 38 个汉字），15px，行高 1.8；标题 Fredoka 40px，节标题 19px。
- 顶部：标题、"最后更新"日期（模板里的常量，填实现这两页的当天，以后改动时一起改）、三句话的总结、"这一页的内容"目录（两列，手机上一列）。
- 每节标题带 `id`，悬停或聚焦时显示 `#` 链接，方便答疑时直接链到某一节。
- 隐私政策的"小凛会记下什么"是一张三列表格（记下什么 / 用来做什么 / 什么时候删除），宽 760px，比正文宽；手机上每行变成一块，"什么时候删除"前面加"删除："。
- 没有贴纸，语气平实，用"我们"指运营者。

### 7.2 隐私政策内容

章节和要点（中英两份，中文试装稿见试装页）：

1. **总结**：只记功能需要的东西（经验值、警告和管理记录、抽奖参与者、各服务器的设置）；不保存聊天内容，不卖数据，不做广告；删除发邮件。
2. **小凛会记下什么**（`#keep`）：用服务器 ID 和用户 ID 记录，不存用户名和头像。表格九行：

   | 记下什么 | 用来做什么 | 什么时候删除 |
   |---|---|---|
   | 经验值和等级 | 等级卡和排行榜 | 按要求删除 |
   | 警告 | `/warnings`，够了自动处罚 | `/warnings remove`、`clear` |
   | 管理记录 | `/case` 查看和修改 | 按要求删除 |
   | 临时封禁 | 到期自动解封 | 解封后删除 |
   | 抽奖（发起人、奖品、参与者、中奖者） | 开奖和重抽 | 退出时删除参与记录，其余按要求 |
   | 播放队列存档 | `/playlist load` | `/playlist delete` |
   | 服务器设置 | 按设置运行功能 | 按要求删除 |
   | 欢迎图片 | 欢迎卡背景 | 换图或移除时 |
   | 黑名单 | 阻止滥用 | 解除时 |

3. **读了但不保存的**（`#read`）：消息内容（自动审核检查、等级只看有没有发言）；成员进出；服务器日志转发的内容在服务器自己的频道里。
4. **网站和控制台**（`#web`）：Discord 登录只请求 `identify` 和 `guilds`；会话 cookie 2 小时失效；语言和日夜间存在浏览器；没有统计、广告、追踪。
5. **用到的其他服务**（`#others`）：Discord、YouTube（`/play`、`/search`）、Spotify（贴 Spotify 链接时）、网易云音乐（`/netease`）、Cloudflare（网站转发）、Google Fonts（网站字体）。
6. **怎么删除数据**（`#delete`）：小凛被移出服务器后，数据不会自动删除；发邮件写上服务器 ID 或用户 ID，30 天内删除并回信；管理员也可以用 `/warnings clear`、`/playlist delete` 删一部分。
7. **运行日志**（`#logs`）：出错时可能记下服务器 ID、用户 ID 和指令名，只用于排查。
8. **年龄**（`#age`）：需满足 Discord 的年龄要求。
9. **这一页的修改**（`#changes`）：改动后更新顶部日期。
10. **联系我们**（`#contact`）。

联系方式：`config.CONTACT_EMAIL`（用 `getattr(config, "CONTACT_EMAIL", "")` 读，旧的 `config.py` 没有这一项也能启动）。有值时显示 `mailto:` 链接；为空时，第 6、10 节改成 GitHub issues 链接，并提醒"issue 是公开的，不要贴出别人的 ID"。地址只写在服务器上的 `config.py` 里，不进仓库。
